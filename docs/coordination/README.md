# A 组双 Codex 协作入口

目标：两个成员分别让自己的 Codex 完成开发、验证、提交和交接。仓库保存共同记忆，成员无需转述上一段聊天。此流程不启动后台任务，也不保证另一端自动醒来；每端开始或继续任务时主动同步。

A1/A2共同交付范围以[A组最终交付清单](A_FINAL_DELIVERY.md)核对；个人任务页记录进度，不单独定义整个A组是否最终完成。

当前完整目标尚在 fork，先读[当前分支与备份](CURRENT_BRANCHES.md)：原仓库main只含已合并的旧阶段，完整整合快照在 fork/main。旧阶段PR关闭表示已由当前整合分支包含，不表示合入原仓库main。

## 首次确定角色

建议发起协作的一端使用 A1，另一端使用 A2。首次由用户在任务中指定，随后 Codex 在各自独立克隆中执行以下其中一条；不要在同一个活动目录运行两端。

```bash
git config --local rnc.role A1
# 另一端执行：git config --local rnc.role A2
```

同一克隆创建的 worktree 可能共享本地 Git 配置；不同角色优先用独立克隆。新克隆需重新确认角色。明确的用户角色指令优先于本地配置；不要在仓库 AGENTS.md 中把所有访问者默认设为 A1。一个角色同一时间仅有一个写代码会话。

| 角色 | 独占范围 | 交接页 |
| --- | --- | --- |
| A1 | src/team-a/lab、app、charts、player；tests/player.test.ts 和 tests/a1-*.test.ts | [A1](A1.md) |
| A2 | src/team-a/viewer；tests/a2-*.test.ts | [A2](A2.md) |

每端可更新自己的交接页、根开发记录中自己的状态行及追加历史。公共入口、配置、依赖、接口、汇总验收记录由协调任务指定单一修改者。B 组的实现职责保持不变。

## 每次启动先恢复真实状态

1. 查看 `git status`、当前分支、角色和 remotes。保护未提交工作，不覆盖、不强制切分支。
2. 确认哪个 remote 指向 KnowCooker/RNC_3D_SIMULATION，哪个指向 lzhdai fork，fetch 两者。完整目标新任务从 fork 最新整合 `main` 创建角色分支；原仓库 main 只作为已正式合并状态核对。已有角色任务先保护未提交工作，再按依赖合入当前整合基线。
3. 读取根 `开发记录.md`、`AGENTS.md`、A 组规则及本目录的两份交接页，再读当前任务相关计划和代码。
4. 查询**原仓库**开放 PR，包含草稿和来自 fork 的 PR，读取同角色/同任务的 PR 正文、最新提交和分支上的交接页。使用 GitHub CLI 时：

```bash
gh pr list --repo KnowCooker/RNC_3D_SIMULATION --state open --limit 100 --json number,title,headRefName,headRepositoryOwner,isDraft,url
```

5. 已有属于本会话的任务就继续；新会话接续同一成员的工作时，先核对执行者标识和用户的接续指令，确认旧会话已停止，再沿用原任务与 PR。属于另一活动会话的同角色任务不重复认领。状态不清楚时保留占用并核对，不按“很久没有提交”自动抢占。
6. 没有活动任务时，从自己队列中取第一个无阻塞的任务。仅访问网页能了解状态；开发、提交和验证需要本地克隆及相应工具。

原仓库 main 是正式已合并状态；fork/main 是完整目标的当前整合快照；开放 PR 是尚待原仓库审查的工作索引。若三者不同，按提交与 PR 状态核对，不把 fork 分支成果写成已进入原仓库 main。

## 先认领，再修改功能

1. 创建任务分支，例如 `a/a1-001-playback` 或 `a/a2-001-markers`。
2. 在自己的交接页填写任务 ID、状态、执行者标识、分支、开始/更新时间、允许文件、验收条件、依赖；同步根开发记录自己的条目。
3. 提交并推送这个认领记录，创建原仓库的草稿 PR，标题以 `[A1-001]` 或对应 ID 开头。PR 正文列出角色、范围、状态、下一步及交接页路径。
4. 再次查询开放 PR，确认没有同角色重复任务后开始修改功能。若同时出现重复认领，后创建的 PR 停止代码修改，保留工作并协调移交；PR 不是原子锁，固定单会话角色和重复检查共同降低竞态。
5. 把 PR URL 补入本角色交接页，在下一次提交中推送。不能只在聊天里说“我已认领”。

没有原仓库写权限时，可在有权限的 fork 推送分支并向原仓库创建 PR。没有推送/PR 权限时可做本地准备，但必须标“仅本地，未取得远端认领”，在角色明确且不会重复他人工作的前提下开展独立工作；不得把本地完成声称为已同步。

## 工作、验证与交接

- 每次只完成一个可验证的小任务，不重写整个 A 组。先复现问题；已有行为正确时记录证据，不为了产生提交改写代码。
- 当前lab-v3日常使用 `pnpm dev`，页面由integration注入真实Worker；`pnpm dev:a`只维护旧demo-v2参考回放。A1/A2可分别使用第二轮证据目录的生命周期夹具和A2-FULL-002的独立viewer夹具，按各README复制到自己的output目录运行；夹具不替代最终真实引擎组合验收。不改原始基准，不重新定义B组指标。
- 独立验证分别运行 `pnpm exec tsx --test tests/a1-*.test.ts`、`pnpm exec tsx --test tests/a2-*.test.ts`，提交前仍执行 `pnpm check`。实时处理器归B，Worker/契约归指定集成者，A1拥有播放时钟，A2只消费时间与场帧。
- 保持 viewer 现有接口兼容。A1 提供统一播放时间、选中通道和残余指标；A2 回传点选事件并消费这些值，不另建播放时钟。
- 跨边界需求写入自己交接页的“依赖/请求”：目标角色、问题、所需接口、验收条件、关联 PR。对方下一次同步读取；不假定写入即获同意。无阻塞部分继续推进。
- 每个可验证批次同时更新自己的交接页和根开发记录，提交并推送。结束前无论完成或阻塞，都保存精确下一步、实际检查和失败信息。
- 按根规则运行 `pnpm check`；UI 变化补截图/操作证据。设备听感、实测延迟、核显及第二机验收须记录真实设备与测量，工具不可用则如实保留待测。
- 状态使用：待认领、进行中、阻塞、待合并、已合并。自动测试通过和产品验收通过分别记录；未合并 PR 不标已合并。
- 证据放自己角色目录，如 `docs/evidence/A1/<任务ID>/`；大体积录屏可用可访问的 PR 附件。不要只写另一端不可访问的本机绝对路径。

## 合并与共同日志

A1 负责 A 组集成；有授权及仓库权限时执行合并，否则报告具体待合并 PR，由有权限的维护者处理。接口涉及 B 组时先完成相应协调。每次只合并一个 PR，核对最新提交的检查结果、变更范围和验证证据，再运行组合流程；不要绕过检查或强推。

后合并的分支先合入最新原仓库 main；根开发记录冲突保留双方历史，只修改自己状态行，不用整个 ours/theirs 覆盖。合并后，任务所属角色在下一次交接提交/PR 中更新自己的页面，标注已合并及合并 SHA；A1 在根开发记录追加集成证据，不改写 A2 交接页。在更新合入前，GitHub 的 merged 状态本身是事实依据。下一任务先核实前一个 PR 的状态。

## 每端可直接使用的启动提示

```text
在 https://github.com/KnowCooker/RNC_3D_SIMULATION 开发，我的固定角色是 A1。
按 AGENTS.md 和 docs/coordination/README.md 恢复状态，检查原仓库开放 PR，
继续本角色任务或认领队列中第一个无阻塞任务。完成开发、实际验证、
更新交接与开发记录、提交推送并创建/更新 PR。遵守目录归属和权限，
不能执行的验收如实保留。以后“继续”均沿用这个角色和流程。
```

另一端只把上面的 A1 改成 A2。后续通常只需说“继续本角色任务”。角色没有指定且没有本地绑定时，只询问一次角色；进度、下一步和历史从仓库读取。

Codex 项目指令机制参考：[官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本目录的认领和交接约定是本项目流程，不是跨会话共享内存或自动调度功能。
