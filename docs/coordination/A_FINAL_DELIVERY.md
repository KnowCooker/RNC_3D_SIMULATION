# A组最终交付标准（完整目标）

确认日期：2026-09-24。本轮再次确认：A组的最终交付是**一套已集成、可运行、可验收的完整展示应用**，不是A1和A2各自提交代码后即算完成。依据用户恢复的[完整目标](../plan/10_FULL_GOAL.md)定义终点，不以当前实现反推需求。旧两周清单移至[历史阶段交付](A_STAGE_V2_DELIVERY.md)，其中单车型、固定工况、不做空间声场等限制不再适用最终目标。

交付责任分为三层：A2让车辆、硬件和空间声场在三维中可看、可操作、可解释；A1让实验配置、信号分析、控制过程和公平试听在页面中可运行；A组共同对A1+A2+B真实引擎的组合体验、Windows交付包和同版本验收证据负责。B组负责数值计算及其正确性，A组负责正确接入和如实呈现，不能用展示层假数据代替最终联调。

## 1. 最终交付是什么

A组交付可在Windows浏览器运行的**交互式车辆RNC展示、调试和试听应用**：理解四类SUV结构、RNC硬件位置、噪声传播和控制原理；调整工况、算法及硬件配置，观察真实计算的信号和空间声场，公平比较控制前后声音。

演示闭环：选车型 → 看结构/拆解/剖面 → 查看硬件与信号 → 改工况及参数 → 增减参考/启禁扬声器 → 运行实验 → 看时域/频域/学习过程/声场 → 同时间比较四座位原声与残余声。实验身份、参数、选择、数据和时间必须一致。

最终判定按“功能实际可操作 → 数据与物理语义正确 → 完整页面联动 → 指定设备与离线包 → 同版本材料可复现”逐层进行。单个组件、单张截图、自动测试、草稿PR或本机候选包都只能证明各自覆盖的部分，不能代替A组最终交付。

实时信号要求不自动增加“任何改制/调参都不中断并保留权重”的承诺，该行为须由接口和产品说明明确。当前回放QA不能替代持续运行验收。

运行模式的约定：预计算模式支持定位；实时模式暂停时冻结时间与样本产出，恢复继续当前学习，重新开始/调参/改制开启新实验。验收须覆盖有界音频队列、补缓冲恢复、后台暂停及过期返回。声场与误差信号按同实验、同绝对时间、同RMS窗比较（当前0.5秒）；滚动场计算保留路径前史。窗不足、低于声压计算底限、实际负降噪分别呈现。

视觉验收须保留同一版本四车型的外观三视角、座舱、动力结构、爆炸与剖面截图，对照来源逐项检查比例与轮廓、曲面连续性、材质/接缝、座舱完整性、架构差异及细节可读性。A2提交差距表，A1核查在完整页面中的显示效果；无法达到参照精细度时保留未完成结论，不以自动测试或一张远景图替代。

关键脚本、原始结果和截图须随提交到达仓库或可访问的PR附件；本机 `output/` 路径不能成为唯一证据。每份报告绑定不可变源码版本及运行文件哈希，角色交接给出准确下一任务与共管接口请求；“PR最新HEAD”仅作找工作入口，不能替代旧验收的版本定位。

## 6. 最终验收门槛

- 逐项走完A1-F1～F7和A2-F1～F7；核对结构与视觉质量，不只检查菜单存在。
- 工况/改制真实改变引擎输入和结果；RNC关闭、零步长、禁用输出有数值证据，不承诺所有工况每一点必然降噪。
- 场由四轮源和输出路径叠加；同位置/同窗的场值与误差信号指标一致；剖面/爆炸不修改物理坐标。
- 最新运行版本通过类型、边界、相关测试、生产构建及全车型组合操作回归。
- 新版连续演示20分钟、至少10次重算、20次播放/对比切换，无崩溃、失控队列、明显持续内存增长；实时模式另覆盖持续计算和停止/重启。
- 沿用设备目标：指定核显、1080p窗口/1280×720内部渲染平均至少30fps；默认计算目标5秒内；实物音画偏差目标≤100ms，无可感知爆音；第二台Windows真实断网启动并重开3次。未达到时记录支持限制，不能用独显/模拟断网替代并称全部通过。
- 完成集成、版本/包校验、说明及交接。权限未就绪可交分支/PR，不写成main已经合并。
