四车均返回 `空间窗口截至 16.00 s`，实时段时钟到15.04秒、场窗口至14.78秒；0页面脚本异常。WebGL报告设备为 **NVIDIA RTX 4070 Laptop GPU/Direct3D11**。rAF 间隔是浏览器呈现节拍的采样，不是 GPU 定时器或实际显示器扫描输出；这些数字**不能当作目标核显≥30fps验收**，也不是音画延迟测量。持续模式在此只测12秒性能段，不替代已单列的20分钟长稳。

当前 `lab-viewer.ts` 根据容器宽高设置 WebGL 缓冲。此次在1080p页面得到1588×618，即981,384像素，超过交付目标1280×720所对应的921,600像素预算约6.5%；比例也不是1280×720。目标含义应按产品视口的宽高比确定等效内部像素上限，不能直接拉伸画面。A2下一批应在自己的 viewer 目录确定分辨率上限/性能策略，保持 CSS 标签清晰及拾取坐标准确，并在**指定核显机器**按四车型默认、全开和实时场组合重新测1080p窗口下的平均≥30fps。A1在完整页面核对布局、控制、信号/声场时间语义；本批只交接事实和复现脚本，不修改 A2 viewer。

复现：检出上述运行源码或仅文档更新后的同源提交，`pnpm check` 构建生产 `dist`；在仓库根目录设置 `PORT=5190` 并执行 `node scripts/serve.mjs`，用预装 Playwright CLI 打开独立 Chromium 会话后运行[脚本](full-app-performance.js)。脚本固定1920×1080视口，每个场景采样8秒、实时场景12秒；报告原始 GPU/缓冲、rAF 间隔与页面状态。实际目标核显须记录具体GPU型号、驱动、浏览器和电源模式；独显复跑不能替代。
