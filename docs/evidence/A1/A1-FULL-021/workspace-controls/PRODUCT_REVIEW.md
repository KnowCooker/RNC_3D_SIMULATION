# 产品流程审计：让体验通向可信、可复现的结论

2026-10-09 · A1 / Codex · 基于当前源码、现有交付记录及本轮检查。网页工具受限，以下区分代码确认的问题与待设备验证的风险。

## 从第一性原理确定产品价值

用户需要完成的是“理解噪声 → 改一个设计 → 看四测点代价与收益 → 形成有依据的下一步”，精细车辆和环境帮助解释这个过程。成功标准应是用户能独立说清 **改了哪里、哪些位置变好或变坏、比较条件是否公平、他人能否复现**。单纯增加模型、角色或指标数量不等于完成这个闭环。

对应三种场景：领导演示需在几分钟内看到问题与证据；教学需主动改变输入并观察后果；工程探索需锁定条件、保留版本和复核记录。三者复用一个实验状态，区别在信息层级和引导强度。

本轮已解决入口隐蔽、主视图被控制面板长期占用、A/B 因果链只靠文字这三类问题；同时修正硬件设置入口、隐藏预览渲染以及新旧环境选择的同步。

## 推进顺序

1. **先证明可用**：解除正常页面验收能力的外部阻塞，按配套脚本完成本轮实机验证；确认干净环境可复建。此项不是让另一位成员改同一批 UI。
2. **再减少重复劳动**：A1 优先保存/恢复实验项目、换车保持道路上下文与工况卡；A2 独立做画质预算及可交付资源。目录与既有 viewer API 继续隔离。
3. **再补证据深度**：A1+B1/B2 按串行协调扩展证据格式和版本来源；A2 负责图表测点到车辆的定位。接口先定义，由指定负责人修改 shared。
4. **最后优化讲述**：将现有引导放到合适入口，形成可重复的三分钟演示：提出问题、只改一个输入、看四测点好坏、保留结论与待验证项。

本轮不以新增功能数量作为完成度。下一轮以“完成一次公平 A/B 所需操作数、刷新后能否继续、其他机器能否复现、关键任务阻断数”验收；性能与可用性指标先测基线，再定改善目标。
