# RNC 四通道演示软件两周开发计划

## 1 结论与版本目标

按四人、每人每周10小时、全程AI辅助开发安排，1至2周可以作为首个可用演示版的交付目标。第1周争取形成可运行的端到端演示，第2周完成核显电脑适配、试听、异常处理和验收。正式排期按2周80个人工小时制定，不把第1周原型等同于已完成全部验证的发布版。

本阶段范围已经收敛为一辆纯电SUV、一种路面、固定4路振动输入、4个车门扬声器、4个头枕附近误差麦克风、FxLMS算法。第七天和第十四天的日期按实际启动日计算；任务书使用第1至第10工作日，每人每天约2小时。

工期成立的条件是采用程序生成的教学模型、固定合成声学路径、已有构建工具和小步AI开发；先交付本地参数化仿真与同步回放。高精度建模、实车预测、复杂声场求解和连续实时调参不进入这次发布门槛。未知电脑性能、AI生成错误和集成返工仍可能影响日期，因此通过逐日交付和预留修复时间控制风险，不作无条件的时间保证。

## 2 已确认约束

| 项目 | 本次执行基线 |
|---|---|
| 人员 | A组2人、B组2人，各人每周10小时，两周每人20小时 |
| 车辆 | 一辆原创双排五座纯电SUV，后置单电机示意，外观和几何适当简化 |
| 路面 | 一种固定沥青路面，默认60km/h；不开放自由路面切换 |
| 参考 | 4个固定单轴振动通道，对应四个悬架安装点 |
| 输出 | 4个固定车门扬声器，全部参与控制 |
| 误差 | 4个固定误差点，前后排左右四个头枕附近，用户已确认 |
| 算法 | 真正的多输入多输出FxLMS，16组控制滤波器及16条次级路径 |
| 声音 | 可以试听任意一个误差点的原噪声和控制后残余声，默认驾驶位 |
| 设备 | Windows浏览器版优先，核显作为基础档；不要求独显完成核心功能 |
| 首次交付 | 第1周内部演示；第2周可分发演示包和验收记录 |

4×4×4分别表示4路参考、4个次级源、4个误差点。实现必须保留扬声器之间的声学交叉影响，不能用4套相互隔离的单通道算法代替后仍宣称完成多通道系统。

## 3 本次必须完成的功能

1. **看得见结构**：可旋转、缩放的一辆纯电SUV；车身、四轮、底盘、动力电池、后电驱、座椅和头枕可辨识；4类硬件点位和名称明确。
2. **看得见内部**：车身隐藏或半透明；简单分层爆炸与一键复位。爆炸只改变展示，不修改声学路径。
3. **看得见控制过程**：信号框图、选中通道的波形和频谱、四误差点原噪声与残余声指标、收敛曲线。
4. **听得出对比**：同一噪声样本、同一时间位置、同一播放增益切换原噪声与控制结果，支持播放、暂停、重播和静音。
5. **能做小实验**：滤波器系数数32或64；步长先开放经过验证的离散值0和0.08。参数更改后重新计算并回放，不承诺运行中连续修改而不重置。
6. **有基本场景**：一种程序生成的沥青材质、轮胎转动、固定车速的路面滚动；不模拟井盖、减速带和真实悬架动力学。
7. **能交付复现**：一份默认实验、独立两组模块、清楚的启动说明、测试报告、源码与依赖锁文件。

第1周保底闭环为“车辆可看、16条次级路径参与计算、曲线可看、驾驶位声音可比”。第2周补齐其它误差点的试听切换、频谱、简单爆炸、参数重新计算、核显优化与发布说明。

## 5 两组分工

**A组交付展示应用。** A1负责页面、图表、播放器和最终集成；A2负责程序化车辆、相机、硬件标记、爆炸、透明和道路。A组通过接口消费计算结果，不计算或伪造降噪效果。算法未接通时可以使用已验证结果开发，界面标明数据来源。

**B组交付计算引擎。** B1负责4×4×4 FxLMS与数值对照；B2负责噪声/路径配置、结果整理、频谱指标、数据导出和引擎适配。B组不依赖真实车辆GLB，不导入Three.js，能在无UI环境运行测试。

两组各32小时计划工作、8小时故障与返工余量。各成员16小时计划工作、4小时余量。环境配置、AI提示、评审、开会和人工验收均包含在这些人工小时中；AI生成及等待时间不假定可以任意忽略，关键输出不能拖过当日交付点。

## 6 最短技术路线

建议单仓库、TypeScript和Three.js，页面采用普通HTML/CSS和少量组件函数，图表先使用Canvas或团队已熟悉的一种库。不同时引入React、Electron、Python服务、数据库和复杂状态框架。数值计算留在独立模块，Worker只是适配层。

车辆全部由代码生成，避免先学习完整Blender流程；资产无远程模型下载依赖。相机采用OrbitControls，不另写相机系统。[Three.js官方文档](https://threejs.org/docs/pages/OrbitControls.html)

开发阶段使用Vite。发布目标为本地可运行的静态演示目录：将依赖打包，避免CDN、动态下载和未打包ES模块。若采用IIFE构建，需另生成引用该脚本的HTML壳；不要把Vite默认输出直接当作可双击的离线包。第1天就在实际电脑验证交付启动方式；双击方式不兼容时，使用团队已装好的Node启动本地服务，并把这个前提写进交付说明。[Vite构建选项](https://vite.dev/config/build-options.html)

耳机播放采用已计算的AudioBuffer，初始点击后启动AudioContext；暂停后重新创建播放节点并从保存位置继续。切换对比使用同时间偏移和约30ms交叉淡化，视频/图表位置跟随音频时钟。AudioBufferSourceNode的复用规则由实现处理，不让UI反复start同一个节点。[MDN音频节点说明](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode)

## 7 计算后回放的确切含义

一次实验先计算16秒，采样率2000Hz；前2秒为无控制基线，2秒后开启FxLMS学习。输出完整x、u、d、a、e及分段指标。准备完成后回放该实验，误差点处e=d+a。暂停只暂停播放；重新计算才创建新的学习过程。

播放中的“原噪声”和“RNC结果”是同工况两路结果的试听/显示选择。切到原噪声不会把已经计算的算法权重倒退，也不能假装是实时冻结学习。界面应使用“对比原噪声”“对比RNC结果”或同样清楚的文字。

实时逐块运行可以沿用相同核心，在第8工作日前全部必交项通过时再尝试。若需要把“连续实时调参、不中断学习”列为本次必须项，则1至2周工期需要重新评估。

## 8 数值可行性起点

随本计划提供一个已实际运行的Python参考算例，具有4路独立输入、4个输出、4个误差点、16条含延时的初级路径和16条次级路径，12条非对角次级路径均非零。采用16组64系数控制滤波器，按全部误差点共同更新权重。

已通过三个固定随机种子、32系数变体、零步长和确定性重复测试。默认16秒合成实验的后4秒，四点平均功率降噪约28.85dB。这个数值来自刻意可控的合成FIR系统，不是实车效果，也不是第一版必须达到的实车性能承诺。产品版本只要求在冻结合成基准上正确复现结果。

参考Python循环在本执行环境约0.6至1.0秒完成16秒过程；这只证明该算例可以批量计算，不代表用户核显电脑上的浏览器性能。本期浏览器验收另设定目标，实测后确定。

提供的参考程序、原始数值文件和驾驶位前后对比音频可帮助两组第1天开始协作；它们不包含车辆界面，不代表完整软件已开发完成。

## 9 交付风险控制

- 第1个工作日冻结接口和发布启动方式，不超过半天讨论架构。
- 第3个工作日必须从A界面读到B的真实结果；算法尚未移植完成时接入参考程序生成的数据，并明确标“参考算例回放”。
- 第5个工作日至少能完成一段可看可听的演示。否则取消全部提升项，保留核心流程，第二周只修主链路。
- 第8个工作日停止新增功能；第9至10个工作日的16个人工小时用于修复、核显适配、复测与交付。
- 在线参数计算若失败，保留已验证默认算例回放供演示；该版本必须标为“演示保底版”，并列出缺失的重新计算功能，不能宣称完整通过计划验收。

本计划取代上一版的当前阶段排期。上一版四类车型、双算法和完整声场作为后续需求池保留，原12至17周MVP估算不适用于本次缩减后的演示范围。
